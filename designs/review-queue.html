Sentinel — identifying the false positives

The list keeps every finding the scanners reported, but the triage report already knows which rows are confirmed and which ones are only a best guess. The design makes that visible: an amber marker and the CVE’s own vendor → product on the row, a Needs review filter, and a review queue that groups the guesses by cluster so a whole group can be dismissed at once.

Amber marker = needs review. It is the triage verdict unverified: the row is shown, but not claimed as affecting you. Confirmed rows show a green check and never get the marker.
CVE vendor → product on line 2. This is the single fact that separates a name collision from a real hit: Fidelis → Network is not the Haskell network library; ? → kernel probably is your kernel.
One action per cluster. Ignore all 15 adds the 15 CVE + package pairs to the applet’s local list at once; Restore all in Settings → Ignored findings brings them back. No root files involved.
